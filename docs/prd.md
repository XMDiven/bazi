## 1. 产品定义

「干支历换算」是一本装在微信里的历书：把任意时刻换算成农历与四柱干支，并把每一步怎么算出来的讲清楚。它的竞争力不在功能多，而在“算得对、说得清、不越界”。

| 项目 | 定义 |
| --- | --- |
| 产品名称 | 干支历换算（备选：四柱历法查询），名称不含“八字” |
| 一句话 | 任意时刻 → 农历、四柱干支、节气，附完整推导过程 |
| 形态 | 微信小程序，无后端，全部功能离线可用 |
| 版本 | v1.0 完整版，一次提审 |

### 1.1 差异化

市面上的同类工具大多只给结果，算法设定藏在底层，结果与别处不同时用户无从判断。本产品的四个差异点：

1. **推导透明**：结果页可展开逐步推导，每一步引用具体的节气时刻或推算口诀。
2. **算法可对比**：在结果页直接切换子时派别、真太阳时，变化的柱位即时标出。
3. **边界主动提示**：临近交节、时辰分界、换日时，告诉用户哪一柱对时间精度敏感。
4. **零采集**：不登录、不定位、不上传，所有数据只在本机。

### 1.2 可衡量目标

| 目标 | 指标 | 上线门槛 |
| --- | --- | --- |
| 算得对 | 节气时刻与公开历表偏差 | ≤ 1 分钟 |
| 算得对 | 换算与反查互验一致率（随机 5,000 个时刻） | 100% |
| 好上手 | 首次使用者完成一次换算的用时（5 人可用性测试） | ≤ 30 秒 |
| 说得清 | 结果页“推导过程”展开率 | 上线 4 周后评估，假设 ≥ 15% |
| 留得住 | 档案保存率（保存档案的用户 / 完成换算的用户） | 上线 4 周后评估，假设 ≥ 20% |

### 1.3 非目标

- 任何解读与预判：性格、事业、婚姻、健康、财富、时运。
- 社交与账号：不做登录、云同步、评论、排行。
- 付费与导流：不做会员、打赏、第三方服务跳转。
- 境外出生地：v1.0 不支持。境外时区与节气绝对时刻的混算需要单独设计和验证，半对的实现比不做更伤信任。

## 2. 合规边界

判定原则只有一条：**只输出可由历法规则唯一推算出的事实，不输出任何对人、对日子的判断。**「这一天的日柱是丙寅」是事实；「这一天宜嫁娶」「丙火日主性格热情」都是判断。微信《小程序平台运营规范》将占卜、算命、风水等封建迷信内容列为禁止项，审核会同时看名称、简介、页面文案和实际功能。

> 规则要点按公开的平台规范整理，条款会更新。每次提审前对照当时的《小程序平台运营规范》与「常见拒绝情形」再核一遍。

合规靠三道防线，缺一不可：产品设计上不提供（本节红线表）→ 文案上不出现（第 14 节，构建时自动扫描）→ 发布前人工自查（第 18 节）。

### 2.1 类目

- 选「工具」大类下与日历/万年历/信息查询相关的子类，按提交时后台实际可选项为准。
- 平台没有“命理/占卜”类目，不寻找近似类目来承载解读功能。
- 个人主体可选类目较窄；如有流量主广告等需求，用企业主体注册。

### 2.3 审核降级预案

所有有审核风险的功能都由本地功能开关控制。被驳回时，只改开关并重新提审，不改代码。按以下顺序逐级关闭，每次只关到驳回理由所指的那一级：

1. 五行计数
2. 纳音
3. 藏干
4. 四柱反查
5. 万年历日详情中的十二时辰干支表

全部关闭后，产品退化为“公农历与干支换算 + 万年历”，这是任何审核尺度下都能成立的形态。

## 3. 用户与关键旅程

主力用户是“已经从别处拿到四柱、想核对对不对”的人，所以产品的重心是**可核对**：算法可见、可切换、可解释。

| 用户 | 典型场景 | 他们的判断标准 |
| --- | --- | --- |
| 核对者（主力） | 拿别处给的四柱来核对 | 能否复现对方的算法设定，不同时能否说清原因 |
| 家庭记录者 | 记录新生儿、父母的农历生日和干支 | 录入快、能存档、以后好找 |
| 文化爱好者 | 了解干支纪时与节气 | 有例子的科普、万年历、节气表 |
| 写作与历史爱好者 | 查历史日期的干支，或由干支反查日期 | 年份范围大、反查准确 |

### 关键旅程

1. **核对**：输入出生信息 → 看结果 → 在结果页切换子时派别或真太阳时 → 展开推导，确认差异来自哪一步。
2. **记录家人**：输入 → 结果页“存入档案”并填称呼 → 日后在「档案」里一点打开。
3. **反查**：只知道四柱 → 选择四组干支 → 得到候选时刻列表 → 打开其中一个的完整结果。
4. **查日子**：打开万年历 → 点某一天 → 看干支、节气、十二时辰干支 → “用这一天换算”。
5. **学习**：在结果页点任意术语 → 弹层看到简要解释 → 进入知识库全文。

不采集性别。它只用于推大运顺逆，而大运不在产品范围内。

### 5.2 默认值与草稿

- 首次打开：日期为今天（按北京时间，与手机时区无关），时间 12:00。
- 之后每次打开：恢复上一次成功提交的输入。从结果页返回时表单保持原样，方便只改一项。
- 从万年历“用这一天换算”进入：日期预填为该日，时间精度预设为“不详”。

### 5.3 校验与反馈

- 控件本身不提供非法选项（不存在的日期、闰月都选不到），校验只是兜底。
- 错误显示在对应字段下方，不用弹窗；“换算”按钮始终可点，点击后滚动到第一个错误。
- 开启真太阳时但未选出生地：出生地字段下方提示“开启真太阳时需先选择出生地”。

### 5.3a 分享入口

- 换算页右下角固定一个圆形“分享”按钮（不随页面滚动），点击直接调起微信“发送给朋友”。
- 卡片标题固定为“干支历换算 · 公历农历与四柱干支对照”，点开进入换算首页；不带表单里的任何输入。
- 按钮用白底细边框，不占用朱砂色（遵守 13 节“朱砂色全页不超过两处”）。

### 5.4 夏令时确认

输入时刻落在 1986–1991 年的夏令时区间时，提交前弹出底部弹层（不用系统弹窗，系统弹窗放不下说明）：

- 标题：这个时间是夏令时吗？
- 正文：1986–1991 年夏季，全国时钟曾拨快 1 小时。如果这是当时钟表上的时间，换算时需要减去 1 小时。
- 按钮：是，减去 1 小时（主）/ 否，按原时间换算
- 选择会记入本次输入，结果页的算法说明中可见，并可在结果页改变。

### 5.5 两个算法设置怎么讲给用户

原则：用户要回答的是“我该选哪个”，不是“这是什么”。所以用大白话做标题、术语降为副标题，并直接展示“对这次输入会改变什么”。

| 设置 | 标题 | 副标题（辅助文字） | 选项 |
| --- | --- | --- | --- |
| 子时派别 | 晚上 11 点后出生，日柱算哪天？ | 子时派别 · 两种说法都常见，不确定就用默认 | 算第二天（23:00 换日）/ 算当天（0:00 换日） |
| 真太阳时 | 按出生地校正时间 | 真太阳时 · 各地天亮早晚不同，新疆与北京相差约 2 小时 | 开关 |

**子时派别的显隐**

- 换算页只在“两种派别得到的四柱或边界提示不同”时显示这一项，否则整行隐藏，沿用当前值，隐藏不会重置用户已选的值。
- 判断用修正后的时刻，与换算完全同一套计算。例：乌鲁木齐 23:30 出生、开启真太阳时，校正后为 21:10，两种派别结果相同，不显示；北京时间 23:30、不开真太阳时，日柱分别为甲戌与癸酉，显示。
- 输入尚不完整（如开启真太阳时但未选出生地）时，按不开真太阳时判断。
- 「我的 › 默认设置」、档案编辑与四柱反查中始终显示；结果页算法条始终可切换。

**真太阳时的即时预览**（开启且已选出生地、时间不是“不详”时显示在开关下方）

- 精确到分钟：“校正后 15:36（北京时间 −2 小时 24 分）”
- 只知时辰：“按时辰中点校正 −2 小时 24 分”
- 第二行列出因此变化的柱：“时柱由 辛酉 变为 庚申”；没有变化时为“四柱不变”。
- 例：2024-02-04 18:00 乌鲁木齐。

**「?」说明**：换算页两项标题旁都有「?」，点开底部弹层（术语卡），内容为两三句话加一个例子，底部“阅读全文”进入 K5 / K6。不离开换算页。

## 6. 换算规则

所有规则都必须能在“推导过程”里用一句话说清楚；说不清楚的规则不上线。

### 6.1 四柱

1. **年柱**：以立春交节时刻为界，不以正月初一为界。
2. **月柱**：以十二“节”（立春、惊蛰、清明、立夏、芒种、小暑、立秋、白露、寒露、立冬、大雪、小寒）的交节时刻为界；月干由年干按五虎遁推出。
3. **日柱**：六十甲子按日连续循环；换日时刻由子时派别决定。
4. **时柱**：子时 23:00–00:59，其后每 2 小时一个时辰；时干由日干按五鼠遁推出。晚子时（23:00–23:59）的时干一律按次日日干推。
5. **子时派别**：“23:00 换日”即晚子时的日柱取次日；“0:00 换日”即晚子时的日柱仍取当日。两派只在 23:00–23:59 产生差异，且只影响日柱。
6. **生肖**：取年柱地支，即按立春划分。若按春节划分会得到不同生肖，结果页同时注明，如“龙（按立春）· 按春节为兔”。

### 6.2 修正层

修正按固定顺序叠加，结果精确到分钟（四舍五入）：

1. **夏令时**：用户确认后减 60 分钟，得到**北京时间**。区间取自 tz 数据库 Asia/Shanghai：1986-05-04 至 09-14、1987-04-12 至 09-13、1988-04-17 至 09-11、1989-04-16 至 09-17、1990-04-15 至 09-16、1991-04-14 至 09-15，均以当天 02:00 为界。
2. **经度修正**：(经度 − 120°) × 4 分钟。
3. **均时差**：按当日计算，全年约 −14.6 至 +16.4 分钟。经度修正 + 均时差得到**真太阳时**。

### 6.3 绝对时刻与当地时刻（本版修正）

初稿把所有修正叠成一个时刻再算四柱，这在交节附近会算错。交节是天文事件，全国同一瞬间发生；“哪一天”“哪个时辰”却是当地时间概念。因此：

| 柱 | 用哪个时刻判定 |
| --- | --- |
| 年柱、月柱 | 北京时间（仅扣除夏令时）与节气时刻比较 |
| 日柱、时柱 | 修正后时刻（开启真太阳时则为真太阳时，否则为北京时间） |

例：乌鲁木齐，2024-02-04 18:00 出生。立春在北京时间 16:27 交节，年柱已是甲辰；若按真太阳时（约 15:36）去比较立春，会错判为癸卯。这条规则不提供开关。

### 6.4 时间精度

| 精度 | 计算方式 | 输出 |
| --- | --- | --- |
| 精确到分钟 | 按输入时刻计算 | 四柱 |
| 只知时辰 | 以该时辰起止时间的中点计算；同时用起、止两端各算一次 | 四柱。两端结果不同时（交节落在时辰内，或真太阳时修正后跨入相邻时辰），给出提示并列出两种可能 |
| 不详 | 以当天 12:00 计算年、月、日三柱；当天有交节时，用 00:00 与 23:59 各算一次 | 三柱。当天交节导致年柱或月柱不确定时，提示并列出交节前后各是什么 |

### 6.5 边界提示

| 类型 | 触发条件 | 提示对象 |
| --- | --- | --- |
| 交节 | 北京时间与最近一个“节”相差 < 30 分钟 | 月柱（立春时还有年柱） |
| 时辰分界 | 修正后时刻与最近的奇数整点相差 < 10 分钟 | 时柱 |
| 换日 | 修正后时刻与换日点（23:00 或 0:00）相差 < 10 分钟 | 日柱 |

初稿对时辰分界也用 30 分钟，会让约一半的时刻都带提示，提示就失去了意义，所以改为 10 分钟。

## 7. 结果页

### 7.1 版式（自上而下）

| 区块 | 内容 | 设计要求 |
| --- | --- | --- |
| 摘要头 | 四柱大字（年 月 日 时四组）；下一行：公历时间 · 农历 · 生肖 | 首屏不滚动可见；干支字号全页最大 |
| 算法条 | 三个可点的标签：子时派别、真太阳时、夏令时（仅在夏令时区间内出现） | 点击打开底部弹层切换，见 7.2 |
| 提示 | 边界提示、时辰不确定提示 | 中性色底条，不用红色、不用警告图标 |
| 四柱表 | 列：年柱 月柱 日柱 时柱；行：天干（五行）、地支（五行）、藏干、纳音 | 点任意单元格弹出术语解释；五行只用小字标注，不着色 |
| 五行计数 | 金 2 · 木 0 · 水 0 · 火 5 · 土 1 | 正文样式，不做柱状图、不高亮最多或为 0 的项 |
| 时间明细 | 输入时间、各项修正分钟数、修正后时间、出生地 | 未修正时只显示一行输入时间 |
| 节气 | 上一个节气、下一个节气及交节时刻 | 点击进入该年节气表 |
| 推导过程 | 逐步推导，默认收起 | 见 7.3 |
| 免责声明 | 见 2.4 | 辅助文字样式 |

底部固定操作栏，从左到右依次为：存入档案（主按钮）、复制、分享、生成图片。已在档案中的结果，主按钮变为“已存为·妈妈”，点击进入编辑。

### 7.2 算法切换

- 在结果页内切换，立即重算，不返回输入页。
- 发生变化的柱位在摘要头和四柱表中加下划线，并弹出轻提示，如“日柱：甲戌 → 癸酉”；无变化时提示“四柱未变化”。
- 开启真太阳时但本次未选出生地：弹层内直接嵌入出生地选择。
- 弹层标题与选项文案同 5.5（如“晚上 11 点后出生，日柱算哪天？”），算法条上的标签保持简写（“23:00 换日”“真太阳时 关”）。
- 切换只影响本次结果，不改「默认设置」；若本次结果是从档案打开的，提示“是否更新到档案”。

### 7.3 推导过程

每一步一句话，引用具体时刻或口诀，以 1990-05-12 12:00 为例：

1. 输入时间：1990年5月12日 12:00（北京时间），未启用真太阳时。
2. 年柱：在立春（1990年2月4日 10:14）之后 → 庚午年。
3. 月柱：在立夏（5月6日 02:35）之后、芒种之前 → 月支为巳；年干庚，按五虎遁得月干辛 → 辛巳。
4. 日柱：按六十甲子连续计日 → 丁丑。
5. 时柱：12:00 属午时（11:00–12:59）；日干丁，按五鼠遁得时干丙 → 丙午。

引用的日期和时刻全部由程序生成，不得手写。

### 7.4 复制与分享

- **复制**的纯文本格式：第一行四柱；第二行公历与农历；第三行算法设定；第四行“——来自干支历换算”。不含出生地和称呼。
- **分享给好友**：卡片标题为“四柱干支：庚午 辛巳 丁丑 丙午”，点开进入换算首页，链接里不带出生信息。
- **生成图片**：先进入预览弹层，用户确认后才保存到相册。图片内容为产品名、四柱表、农历与生肖、免责声明，不含出生地和称呼。

### 7.5 状态

| 状态 | 表现 |
| --- | --- |
| 参数无效（链接被截断、旧版本数据） | 空状态：“没能读取这次换算”，按钮“重新换算” |
| 计算异常 | 错误状态：“换算出错了”，按钮“反馈问题”；同时上报错误事件（不含输入数据） |
| 存档失败（存储已满） | 轻提示“保存失败，可在「我的 › 数据与隐私」清理”，结果页本身不受影响 |

## 8. 四柱反查

用户选定四组干支，产品列出 1900 年至今天之间所有符合的时辰。只列过去的时刻，是为了从产品上杜绝“择时”用途（见 2.2）。

### 8.1 输入

- 四个选择器：年柱、月柱、日柱、时柱，每个都从六十甲子中选。时柱可选“不填”。
- 选项联动过滤：选定年柱后，月柱只列出五虎遁允许的 12 个；选定日柱后，时柱只列出五鼠遁允许的 12 个。不可能的组合从控件上就选不到。
- 子时派别：沿用「默认设置」，可在页内切换。
- 反查不使用真太阳时和夏令时，结果一律为北京时间，并在结果页顶部注明。

### 8.2 结果

- 按时间倒序列出。每条显示：公历日期与星期、时辰起止时间、农历日期，例如“1990年5月12日 周六 · 11:00–12:59 · 农历四月十八”。
- 若某条的时辰内发生交节，时间段只列出真正符合的那一段，如“16:28–16:59”（立春于 16:27:07 交节，按整分钟计从 16:28 起符合），并加注“含交节”。
- 未填时柱时，按日列出。相邻的时间段合并为一条，例如“23:00 换日”时的子时显示为“3月10日 23:00 – 3月11日 00:59”。
- 点击任一条，进入该时刻的完整结果页：时间精度设为“只知时辰”，未填时柱时设为“不详”。
- 无结果：“1900 年至今没有符合这组四柱的时刻”，并附一条知识库链接，解释为什么有些干支组合不存在。

### 8.3 正确性要求

反查的每一条结果，换算回去必须得到原来的四柱；反过来，任意一个过去的时刻换算出的四柱，反查结果里必须包含该时刻。这条双向一致性在测试中用 5,000 个随机时刻验证（1.2 节）。

## 9. 万年历、日详情与节气表

万年历是“干净的历书”：只有日期、干支、节气和节日，没有任何宜忌类信息。这是它与市面上“黄历”类工具的根本区别，也是合规底线。

### 9.1 月历（Tab 页）

- 头部：“2026年11月 · 丙午年”，右侧“今天”按钮；点年月标题打开年月选择器；左右滑动切换月份。
- 月格：周一至周日，6 行固定高度，切月时不跳动。每格上行为公历日，下行为副标签，优先级：节气 > 节日 > 农历初一显示月名 > 农历日。
- 今天用实心圆形强调，选中日用描边；非本月日期降低透明度。
- 月格下方是选中日的摘要：公历、农历、年月日干支、生肖；若当天交节，显示交节时刻；底部一行“距小雪还有 5 天”及“节气表”入口。
- 节日只显示白名单：元旦、劳动节、国庆节、春节、元宵节、端午节、七夕节、中秋节、重阳节、腊八节、除夕。不显示宗教节日和西方节日。

### 9.2 日详情

- 内容：公历（含星期）、农历、年月日干支、生肖、节气（若有，含交节时刻）、节日（若有）。
- 十二时辰干支表：13 行（早子时到晚子时），每行为时辰名、起止时间、干支。晚子时一行按当前子时派别标注“日柱已入次日”或“日柱仍为当日”。
- 操作：“用这一天换算”，跳到换算页并预填日期。
- 不显示：宜忌、冲煞、彭祖百忌、吉神凶煞、胎神、九星、黄道黑道、时辰吉凶。历法库本身提供这些数据，代码中也不得调用相应接口。

### 9.3 节气表

- 顶部是年份选择（1900–2100），默认今年。
- 列表展示当年 24 个节气：名称、交节日期与时刻（到分）、星期；“节”与“中气”用小标签区分。
- 已过的节气降低透明度，下一个节气标注“即将到来”。
- 点击任一行进入该日详情。
- 底部注明：“时刻为北京时间，由天文算法计算，与公开历表偏差不超过 1 分钟。”

## 10. 档案与最近

“最近”是系统自动记录的，“档案”是用户主动保存并命名的。两者分开，是为了让档案里只有用户在乎的人，不被随手的查询淹没。「档案」Tab 顶部用分段控件切换“档案 / 最近”。

| 项目 | 档案 | 最近 |
| --- | --- | --- |
| 产生方式 | 结果页“存入档案”，或从最近中“存为档案” | 每次成功换算自动写入 |
| 容量 | 100 条，达到上限时提示，不自动删除 | 20 条，超出删最早的 |
| 字段 | 称呼（必填，≤ 10 字）+ 完整输入 + 算法设定 | 完整输入 + 算法设定 |
| 去重 | 同一输入再次保存时提示“已在档案中：妈妈”，并询问是否打开 | 同一输入只保留一条，移到最前 |
| 排序 | 置顶在前，其余按最近打开时间 | 按换算时间倒序 |
| 操作 | 打开、编辑、置顶、删除（左滑）；按称呼搜索 | 打开、存为档案、删除（左滑）、全部清空 |

### 10.1 列表项

- 档案：第一行称呼；第二行四柱；第三行“公历 1990年5月12日 12:00”或“农历 1990年四月十八 · 时辰不详”。
- 最近：第一行四柱；第二行输入时间；右侧为相对时间，如“3 分钟前”“昨天”。

### 10.2 编辑档案

- 可改称呼和全部输入项，表单与换算页一致。
- 保存后显示新的四柱。若四柱发生变化，先提示“四柱将变为 …”，用户确认后再保存。
- 删除前二次确认：“删除「妈妈」？删除后无法恢复。”

### 10.3 空状态

- 档案：“还没有档案。换算后点「存入档案」，下次不用再输入。”按钮：去换算。
- 最近：“还没有换算记录。”
- 搜索无结果：“没有找到「xx」。”

## 11. 知识库

知识库只讲“历法是怎么算的”，不讲“它意味着什么”。每篇不超过 800 字，至少带一个由程序生成的实例。

| 编号 | 文章 | 要点 |
| --- | --- | --- |
| K1 | 天干地支与六十甲子 | 十天干、十二地支、六十甲子表、各自的五行属性 |
| K2 | 四柱是怎么来的 | 年月日时各自如何定；“四柱干支，俗称生辰八字” |
| K3 | 节气与换月 | 节与中气；为什么以立春换年、以“节”换月 |
| K4 | 五虎遁与五鼠遁 | 月干、时干的推算口诀与对照表；为什么有些组合不存在 |
| K5 | 真太阳时 | 经度修正与均时差；为什么年柱、月柱不用它 |
| K6 | 早晚子时 | 两派差异只影响 23:00–23:59 的日柱 |
| K7 | 夏令时 | 1986–1991 年的具体区间 |
| K8 | 藏干表 | 十二地支各自藏干的对照表 |
| K9 | 纳音表 | 六十甲子对应的纳音名称，不解释其“含义” |
| K10 | 为什么和别处算的不一样 | 逐条列出子时派别、真太阳时、夏令时、立春与春节、时区等差异来源 |

- **术语弹层**：结果页、日详情中的术语可点击，弹层给出一句话定义和“阅读全文”链接。
- **内容审核**：每篇由产品负责人对照 2.2 红线表逐句审读；纳音、藏干只给名称和对应关系。

## 12. 我的与设置

「我的」页不放头像和昵称，顶部只有一句“全部数据仅保存在这台手机上”。这是对零采集承诺最直接的表达。

| 分组 | 条目 | 说明 |
| --- | --- | --- |
| 默认设置 | 子时派别、真太阳时、默认出生地 | 只影响之后的新换算；标题、副标题与选项文案同 5.5，子时派别始终显示；各项旁有「?」链到对应知识库文章 |
| 学习 | 知识库 | 文章列表 |
| 数据与隐私 | 隐私说明、复制全部档案、清空最近、清除全部数据 | “复制全部档案”把档案转为纯文本，方便换机时自行保存；清除全部数据需输入“清除”二字确认 |
| 帮助 | 意见反馈 | 使用微信官方反馈入口 |
| 关于 | 版本号、更新说明、服务协议、免责声明 | 更新说明按版本倒序，每条不超过 3 行 |

换机迁移不做导入功能：导入需要解析用户粘贴的文本，容错成本高、使用频率低，留待有真实需求后再评估。

## 13. 设计规范

视觉调性是“一本精排的历书”：纸面感、字即界面、克制用色。它要让人觉得可信，而不是神秘。

### 13.1 原则

1. **一屏一个重点**：每个页面只有一个最大的元素，结果页是四柱，换算页是“换算”按钮。
2. **数字与依据并列**：凡是修正过的数值，旁边就有修正了多少、为什么。
3. **东方但不玄学**：不用八卦、太极、罗盘、符咒、星空、金色渐变等意象，不用红黄“喜庆”配色。
4. **五行不着色**：按五行给干支上色会被解读为“强弱”，一律不用。

### 13.2 色彩令牌

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| --paper | #F7F5F0 | #141413 | 页面背景 |
| --surface | #FFFFFF | #1E1E1C | 卡片、弹层 |
| --ink | #1C1C1A | #ECEAE4 | 正文、干支 |
| --ink-2 | #6B6862 | #A29F97 | 辅助文字 |
| --line | #E4E0D8 | #2E2D2A | 分割线、描边 |
| --accent | #A8432E | #D9735C | 主按钮、选中态、“今天” |
| --on-accent | #FFFFFF | #141413 | 主按钮上的文字 |
| --notice | #F4EEDF | #2A261C | 提示条底色 |

对比度已逐对核算：正文与背景 ≥ 15:1，辅助文字 ≥ 5:1，主按钮文字 ≥ 5.7:1。深色模式的主按钮若用白字，对比只有 3.2:1，所以改用深色字。朱砂色全页同时出现不超过两处。

### 13.3 字体与间距

以下尺寸均按 750 设计稿宽度计（rpx）。

| 层级 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| 干支大字 | 64 / 600 | 结果页摘要头 |
| 标题 | 36 / 600 | 页内区块标题 |
| 正文 | 30 / 400 | 表格、列表、说明 |
| 辅助 | 26 / 400 | 注释、五行小字、免责声明 |
| 最小 | 24 / 400 | 月历副标签，仅此一处 |

- 字体使用系统字体，不加载网络字体，以保证离线可用；数字使用等宽数字。行高 1.6。
- 间距以 8 为基数：8 / 16 / 24 / 32 / 48。页面左右留白 32，卡片圆角 16，可点击区域不小于 88。

### 13.4 组件清单

| 组件 | 用在 | 要点 |
| --- | --- | --- |
| 摘要头 | 结果页 | 四组干支等宽排列，窄屏不换行 |
| 四柱表 | 结果页、分享图 | 3 或 4 列自适应；单元格可点 |
| 算法条 | 结果页 | 标签式按钮，点击打开底部弹层 |
| 分段控件 | 换算、档案、设置 | 2–3 段 |
| 日期时间弹层 | 换算、档案编辑 | 公历/农历切换 + 滚轮，确认按钮在右上 |
| 城市选择弹层 | 换算、设置 | 搜索优先，省市两级列表兜底 |
| 干支选择弹层 | 反查 | 6×10 网格，不可选项置灰 |
| 提示条 | 结果页 | 中性底色 + 文字，无图标 |
| 空状态 | 档案、最近、反查 | 一句说明 + 一个按钮，不用插画 |
| 底部操作栏 | 结果页 | 适配底部安全区 |

### 13.5 动效

- 只用系统页面转场；弹层入场 200ms 缓出。
- 算法切换后，变化的柱位下划线保留，不做闪烁。
- 不做启动动画和引导轮播。

### 13.6 无障碍与适配

- 微信字体调到最大时不重叠、不截断：容器不写死高度，四柱表允许横向缩小字号但不低于 26。
- 深色模式全页面支持，导航栏与底部 Tab 栏同步切换。
- 读屏：四柱表每个单元格有完整读音标签，如“年柱，天干庚，五行金”。
- 屏幕宽度 320–430pt 全覆盖；PC 与平板端内容居中，最大宽度 750rpx。

### 13.7 设计交付物

应用图标、底部 4 个 Tab 图标（含选中态，尺寸 81×81 的 PNG）、分享封面图（5:4），以及上述组件的高保真稿。未交付前，开发使用无图标的纯文字 Tab 栏。

## 14. 文案规范

文案要像工具书：平实、准确、短句。一句话能说清的不写两句。

### 14.1 语气与格式

- 称呼用“你”；不用感叹号、不用网络流行语、不用表情符号。
- 日期展示为“1990年5月12日”；同一年的列表内可省略年份；时间用 24 小时制“08:05”。
- 负数分钟用全形减号“−”，保留 1 位小数，如“经度 −129.5 分钟”。
- 按钮用动词：“换算”“存入档案”“生成图片”；不用“立即”“马上”等催促词。

### 14.2 术语表

统一使用：四柱、年柱、月柱、日柱、时柱、天干、地支、藏干、纳音、节、中气、交节、真太阳时、均时差、子时派别、早子时、晚子时。不混用同义词，例如不写“时辰柱”“日主”。

### 14.3 禁用词

代码、文案、图片、分享标题、后台简介一律不出现：算命、测算、占卜、命理、命盘、运势、运程、吉凶、预测、改运、大师、风水、开光、财运、姻缘、排盘、宜忌、冲煞、喜用、旺衰、十神、神煞、大运、流年。只有免责声明原文例外，其中的“预测”是否定用法。构建时自动扫描，命中即失败。

### 14.4 固定文案

| 位置 | 文案 |
| --- | --- |

## 15. 数据、隐私与权限

所有换算都在本机完成，不存在任何服务器。产品只用到两个隐私相关能力：写入剪贴板和保存图片到相册。

### 15.1 本地数据

| 数据 | 上限 | 用途 |
| --- | --- | --- |
| 档案（称呼 + 输入） | 100 条 | 用户保存的人 |
| 最近（输入） | 20 条 | 自动记录 |
| 默认设置 | 1 份 | 子时派别、真太阳时、默认出生地 |
| 上次输入 | 1 份 | 换算页恢复表单 |
| 隐私协议同意状态 | 1 份 | 由微信管理 |

全部数据预计不超过 100KB，远低于小程序本地存储 10MB 的上限。存储读写失败时，不影响换算本身。

### 15.2 隐私接口与授权

| 能力 | 微信接口 | 何时触发 |
| --- | --- | --- |
| 复制结果、复制全部档案 | wx.setClipboardData | 用户点“复制” |
| 保存图片 | wx.saveImageToPhotosAlbum | 用户在预览弹层点“保存” |

- 首次触发任一隐私接口时，弹出自定义隐私授权弹层（通过 wx.onNeedPrivacyAuthorization 触发）：“使用此功能前，请阅读并同意《干支历换算隐私保护指引》。”按钮为“同意”和“不同意”。不同意时，只是本次操作不生效。
- 不在启动时索取任何授权。
- 已拒绝相册权限时，提示“需要相册权限才能保存图片”，并提供“去设置”按钮。
- 公众平台后台的「用户隐私保护指引」中声明上述两项，文字与「数据与隐私」页一致。隐私接口清单以微信官方最新公布为准，提审前核对。

### 15.3 不做的事

不登录，不获取 openid、头像、昵称、位置、手机号；不发起任何网络请求；不接入第三方 SDK。统计只使用微信内置的数据分析，上报参数中不包含任何出生信息或称呼（见第 17 节）。

## 16. 非功能需求

准确性优先于一切，其次是速度。每一项都必须有可执行的验证方式。

| 类别 | 要求 | 验证方式 |
| --- | --- | --- |
| 准确性 | 节气时刻与公开历表偏差 ≤ 1 分钟 | 自动化测试抽样对照（含 2000、2023–2025 年立春） |
| 准确性 | 换算与反查双向一致 | 5,000 个随机时刻的属性测试 |
| 准确性 | 在任意手机时区下结果一致 | 全部测试在 3 个时区各跑一遍 |
| 性能 | 冷启动到换算页可操作 < 1.5 秒（中端安卓机） | 真机性能面板 |
| 性能 | 单次换算 < 50 毫秒；反查 < 500 毫秒；月历切换 < 100 毫秒 | 自动化性能测试 + 真机复核 |
| 包体积 | 主包 ≤ 1.5MB，总包 ≤ 4MB | 开发者工具「代码依赖分析」 |
| 兼容 | 基础库 ≥ 3.0.0；iOS 与 Android 微信当前版及前两个大版本 | 真机矩阵：2 台 iOS + 3 台 Android |
| 离线 | 全部功能在飞行模式下可用 | 真机走查全部 5 条关键旅程 |
| 稳定性 | 存储异常、参数异常、计算异常均有对应界面状态，不白屏 | 故障注入测试 |
| 测试 | 核心逻辑行覆盖率 ≥ 90%；5 条关键旅程有端到端自动化测试 | CI 输出覆盖率报告 |

分包策略：四个 Tab 页、结果页、反查页、档案编辑页放主包；日详情、节气表、知识库、数据与隐私、关于放分包。历法库约 430KB，在主包中共用。

## 17. 指标与埋点

只用微信内置的数据分析与自定义事件。**任何事件参数都不得包含日期、时间、干支、城市或称呼**，只记录功能使用的方式。

### 17.1 核心指标

| 指标 | 口径 | 用途 |

## 18. 发布、审核与运营

v1.0 一次提审全部功能。审核风险靠第 2 节的红线表和降级开关控制，而不是靠拆小版本。

### 18.1 发布流程

1. 全部自动化检查通过：单元测试、时区测试、禁用词扫描、端到端测试。
2. 体验版内测：不少于 10 人、不少于 5 天，覆盖 iOS 与 Android、大字体、深色模式。
3. 5 人可用性测试：首次换算 ≤ 30 秒。
4. 人工自查（18.2）。
5. 提审。备注写明：“公历、农历与干支历之间的日期换算工具及万年历，不含任何解读、宜忌或择日功能。”

### 18.2 提审前人工自查

- [ ] 名称、简介、类目、关键词不含禁用词
- [ ] 结果页、日详情、分享图、知识库逐页对照 2.2 红线表
- [ ] 万年历与日详情中没有任何宜忌类信息
- [ ] 反查结果不包含未来时刻（可将手机日期调到立春前后验证）
- [ ] 隐私授权弹层在复制、保存图片时正常弹出；后台隐私指引已更新
- [ ] 无付费入口、无外链、无诱导分享
- [ ] 降级开关逐个关闭后，页面均无空位或报错

### 18.3 驳回处理

按驳回原文定位到页面 → 按 2.3 的顺序关闭对应开关 → 在更新说明中记录 → 重新提审。同一理由驳回两次，再考虑调整产品范围。

### 18.4 运营

- 每周处理一次微信反馈。解读类诉求统一回复：“本工具只提供历法换算，暂无此计划。”
- 每月最多发布一个小版本；以修复和体验打磨为主，新功能必须先写入本文档并通过红线评审。
- 上线 4 周后复盘第 17 节指标，定下正式目标值。

## 19. 已定决策与待决事项

### 19.1 已定决策

| 决策 | 理由 |
| --- | --- |
| 年柱、月柱按北京时间比较节气，日柱、时柱按修正后时刻 | 交节是同一瞬间的天文事件；全部用真太阳时会在交节附近算错 |
| 生肖按立春划分，与春节不同时加注 | 与年柱保持一致，同时不让按春节理解的用户困惑 |
| 时辰与换日边界提示阈值 10 分钟，交节 30 分钟 | 30 分钟的时辰阈值会让一半的时刻都带提示 |
| 反查只列今天及以前 | 杜绝择时用途 |
| v1.0 不支持境外出生地 | 境外时区混算需单独设计，不做半对的版本 |
| 不采集性别 | 只用于大运，而大运不在范围内 |
| 万年历节日用白名单 | 历法库自带的节日含西方与宗教节日，与产品调性不符 |
| 不做档案导入 | 低频、高容错成本；先用“复制全部档案”满足备份 |
